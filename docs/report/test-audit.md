# Automated test audit

Reviewed the COMP41670 2026/27 project brief, sections 3 and 5, against the [documented invariants and design decisions](../design/Invariants.md). The table gives a named test and a concrete failure condition for each rule. Registration, offer publication, request creation, proposal management, selection, confirmation, cancellation, suspension, reinstatement, grants, personal queries and the circulation report are exercised through their public boundaries. The [CLI test log](cli-test-log.md) records the installed menu checks.

## Test design

Week 8, Lecture 16 asks whether an assertion can fail, whether boundaries and negative paths are present, whether results are specific, and whether each expectation follows from a requirement. For example, the brief gives a 60-credit hourly rate and a 5% floored levy. Starting with 120 each, a one-hour settlement must leave 57 with the requester, 180 with the helper and 3 with the fund. The application test uses those independent figures. A line-coverage percentage would not detect payment to the wrong account.

The pyramid uses small owner tests for pure rules and exact endpoints, real application tests when two owners must publish together, and installed CLI runs for navigation and visible state. The team interprets R11 as a rolling calendar month with the anniversary excluded and R14 using whole simulated dates. R9 applies to the scheduled session date; confirmation may be recorded afterward. Setup and legacy implementation-characterisation tests are not substitutes for the behavioral checks below.

## Gaps addressed

- The documented 480-minute limit applies to each session. Added an engagement-level test that accepts two distinct 300-minute agreements for the same helper on the same date and checks both returned agreements.
- Existing settlement tests covered individual amounts but did not compare the same hour across skills. Added a real Gardening/Cooking comparison with exact payment, levy and account balances.
- The suite rejected a hold one credit beyond the floor and allowed a hold at the floor. Added real two-party settlement ending at exactly -180 posted and zero held.
- The confirmation coordinator had rollback coverage with test doubles. Added an injected last-step failure with the real engagement manager and ledger, then retried and counted the posted entries.
- Strengthened the application proposal test: three refusals previously accepted any failure. It now checks BUSINESS_REJECTION and re-queries the request after an unskilled helper, a self-proposal and an out-of-window date.
